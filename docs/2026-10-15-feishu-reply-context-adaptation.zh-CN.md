## 目标与边界

用户在飞书对历史消息点“回复”并输入要求时，中间件按 `parent_id` 读取直接父消息，将其原文写入现有 `quotedMessage`，随本次普通输入交给 Codex。私聊和已启用、完成配对／成员登记且真正 @Bot 的群聊共同支持。

保留完整引用内容，不添加自动摘要、裁剪或去重。只读取直接父消息，不递归追溯 `parent_id/root_id`，不读取整段聊天记录，不触发整段 Codex 历史重新加载。命令和交互式问题答案只解析本次输入，不查引用原文。

正常文本、富文本／Markdown、图片和文件使用已有内容与附件链路；撤回、读取失败、会话不匹配或尚不支持的消息类型保留引用 ID 并明确说明。渠道请求失败不能中断本次普通输入，也不把接口错误或凭据拼进模型输入。

## 已实现的输入链路

1. 飞书 adapter 只把入站 `parent_id` 标记为待恢复引用。仅有 `root_id` 不推断成引用；不处理自引用 ID。
2. Bridge 完成配对、群成员登记和黑名单判断，先处理命令与交互式问题答案。普通输入才调用可选的通用 `hydrateQuotedMessage` hook；其他渠道保持已有链路。
3. 飞书通过现有官方 SDK `im.message.get` 请求直接父消息，核对返回消息 ID 和当前 `chat_id`。按文本、富文本／Markdown、图片或文件恢复内容。
4. 图片／文件资源请求使用父消息 ID，而不是当前回复 ID。可用附件接入已有上传目录和 Codex 输入；群内附件保留本次请求者身份，后续权限检查仍以本次请求者为准。不可用的引用附件只形成说明，不阻断本次文字要求。
5. `quotedMessage` 与本次输入分开保存，最后拼成“用户引用的历史消息（仅作为上下文）”。原文中的 `/stop` 等文字不会被中间件当命令执行；不新增 Codex RPC，也不因引用重新加载会话。
6. 初始日志显示本条／父消息 ID 及等待读取状态；恢复后追加本地“引用”记录，显示成功、缺失、撤回、超时、会话不匹配等分类，以及可用的数字错误码。引用恢复记录不复制原文、原始接口错误或凭据，不向飞书额外发送通知。

查询前、查询后、附件下载后及向 Codex 交接前复查授权。读取期间撤销配对、拉黑发送者或停止 Bridge，会丢弃未交付的结果；已有群排队、附件来源及撤权检查继续生效。已经写入本地或交给 Codex 的内容不能因此被撤回。

## 使用方式与限制

- 私聊：对旧消息点“回复”，输入“按这个方案继续”等普通要求。群聊：对旧消息点“回复”，在新输入中真实 `@Bot` 并说明要求；只点回复仍需遵守原有 @Bot、配对和成员登记规则。
- 回复机器人问题时照常输入 `/a1`、`/a2 补充要求` 或自由输入题的 `/a1 自定义内容`；三题逐题回答。即使引用了题目，也不会再查题目原文或把题目内容混入答案。
- 富文本兼容标准 `content` 以及 `zh_cn/en_us` 等语言包装，保留 Markdown、标题、段落、链接和提及名称。引用正文不做长度预算、自动摘要或去重。
- 只取直接父消息。卡片、合并转发、音视频等尚未支持的类型明确提示；不展开转发、聊天历史或整条回复链。
- 元数据读取默认最多等待 10 秒，超时后继续处理当前要求并带上引用不可读取说明；不在应用层重试。当前 SDK 请求接口不提供逐请求取消参数，因此这个时限只限制等待，底层请求可继续结束，其迟到结果被忽略。附件复用既有下载链路，不宣称整次附件读取也有 10 秒上限。
- 需要机器人具有读取该消息及资源的权限。权限不足、消息被删除或接口未返回原文时，Codex 会得到明确的缺失说明，日志保留引用 ID 和错误分类；本批未修改租户权限或使用真实账号联调。
- 本批只实现入站引用恢复，不升级飞书 SDK，不发布 npm 包，不实现长文本分段或微信发送恢复。

源码更新后需要重新构建并重启使用该源码的服务。本次没有改动正在运行的渠道进程；已经安装的旧版全局 npm 包不会随 Git 推送自动更新。
