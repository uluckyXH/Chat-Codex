# 飞书群聊使用说明

更新：2026-10-15。源码已开放，机器人仍默认不接收群消息。自动化验证与未完成的真实租户验收见[测试报告](../reports/tests/2026-10-15-feishu-group-implementation.md)。

## 开启和首次接入

1. 停止旧服务，使用更新后的源码。在项目目录运行 `npm run chat-codex`，会先构建并打开 TUI；首次安装源码依赖时先执行 `npm ci`。进入「管理渠道 → 飞书渠道详情 → 6. 开启群聊接收」确认开启，再返回首页启动服务。若新版服务已经运行，可以在**已配对的飞书私聊**发送 `/group on`。关闭用 `/group off`，旧 `/grop` 别名继续支持。
2. 把机器人加入目标飞书群，在群里 **@机器人** 发一条消息。配对码只出现在运行服务的本机日志中，在该群发送 `@Bot /pair <配对码>`。
3. 完成配对的人是该群唯一超级管理员。重复配对不会替换超管或解除黑名单。
4. 每位使用者发送 `@Bot /name 展示名` 登记。名称只影响显示，权限按稳定 Open ID 判断。
5. 使用已绑定的群会话，或在 `auto_new` 策略下自动创建一个群会话。需要选择已有会话或工作目录时，先从本机「聊天绑定」配置；群内不开放 `/new`、`/use`、`/resume`、`/sessions`。

每条文本、命令、图片和文件都必须 @机器人。只有 @所有人不会触发，未 @ 的资源不会进入共享附件池。不同机器人、账号、群有独立 route。

本轮只提交源码，没有发布新版 npm 包；已安装的旧版全局 `chat-codex` 不会因为 Git 推送而自动获得此功能。

## 角色和命令

以下群命令均需要加 `@Bot`。用完整 `ou_…` Open ID 替换 `<成员>`，也可真实 @ 一位成员，不能只输入展示名。

| 操作 | 命令 | 谁可以做 |
| --- | --- | --- |
| 本人名称、身份、帮助 | `/name [名称]`、`/whoami`、`/help` | 未拉黑成员，允许配对前 |
| 查看管理员、审批策略 | `/group admins`、`/group policy` | 超管、管理员 |
| 添加或撤销管理员 | `/group admin add <成员>`、`/group admin remove <成员>` | 超管 |
| 拉黑、解禁、查看黑名单 | `/group block <成员>`、`/group unblock <成员>`、`/group blocked` | 超管、管理员，受目标层级限制 |
| 管理员审批或开放审批 | `/group approval restricted`、`/group approval open` | 超管 |
| 处理一次审批 | `/OK <编号>`、`/NO <编号>` | 默认超管、管理员；开放模式含普通成员 |
| 执行任务并发送交付文件 | `/sendfile <任务要求>` | 超管、管理员 |
| 查看运行状态、停止、清共享待处理项 | `/status`、`/stop`、`/cancel` | 超管、管理员 |
| 模型、执行权限、协作模式、目标、压缩与上下文刷新 | `/model`、`/permission`、`/plan`、`/code`、`/goal`、`/compact`、`/context-refresh` | 超管 |

管理变更会展示具体影响，再要求操作者在 **60 秒内**发送 `/group confirm <确认码>`。不能由其他人代确认，也不能拿 `/OK` 审批编号确认管理变更。中途权限版本变化需重新发起。

管理员只能管理普通成员，不能操作自己、其他管理员或超管。管理员也不能解开由超管、本机或旧版本来源不明的封禁。超管拉黑管理员时同时撤销其角色；解禁后是普通成员，不自动恢复管理员身份。拉黑只作用于当前群的机器人能力，不踢出飞书群，也不影响其私聊或其他群。

开放审批只扩展单次审批资格，不扩展文件或管理权限。多个审批同时存在时必须指定编号；群里不支持 `/P` 会话范围批准。审批回写失败且无法确定远端是否接收时显示“结果待核实”，不会自动重复批准。

## 群共享附件和文件输出

已登记且未拉黑成员可以 `@Bot` 上传图片或文件，其他已登记成员可继续 `@Bot` 补充处理要求。共享池最多 5 个附件、10 分钟过期，提示和 Codex 输入都会标明来源。管理员可 `/cancel` 清空。

黑名单在下载前检查；拉黑后尚未投递的附件和补充按来源过滤，其他人的内容保留。已经进入 Codex 上下文的内容不能撤回。

`/sendfile` 在接收命令、排队执行、上传和实际发送前复查原始发起人的权限。撤销管理员或拉黑后，后续文件不再发送；后来的发言人或审批人不会接管原任务的文件授权。图片同样受此检查。回复优先关联原消息，失败时回退到当前群。

自动把长文本转文件属于独立功能，本轮没有增加此路径，也没有把普通成员的文本自动当作文件输出。

## 回复历史消息

对群里的旧消息点“回复”，在新的输入中真实 `@Bot` 并写明要求，例如“按这个方案继续”。完成配对和名称登记、未被拉黑的成员可用。中间件会读取直接被回复消息的文字／Markdown 和可访问附件，让 Codex 知道引用了什么；不会展开整段群历史或整条回复链。私聊同样支持，不需要 @Bot。

命令和交互式问题答案只处理本次文字。回复题目时继续按提示发送 `@Bot /a1`、`@Bot /a2 补充要求`，自由输入题使用 `@Bot /a1 自定义内容`；三题依次作答，不必重新粘贴题目。

原消息撤回、机器人无权读取或附件已不可用时，引用上下文会明确说明缺失，本机日志显示消息 ID 和恢复结果。支持类型、授权复查及联调限制见[飞书入站回复原文适配](2026-10-15-feishu-reply-context-adaptation.zh-CN.md)。

## 本机权限管理和恢复

入口：「聊天绑定 → 群绑定详情 → 6. 群权限管理」。界面显示当前超管、管理员、黑名单及审批策略，输入以下操作后按提示确认：

```text
members                      查看最近发现的成员、Open ID 和角色
audit                        查看最近 10 条审计
refresh                      刷新状态
transfer ou_目标             设置或转移唯一超管
clear_super                  清空超管，暂停审批、发文件和聊天管理
admin_add ou_目标             添加管理员
admin_remove ou_目标          撤销管理员
block ou_目标                 拉黑
unblock ou_目标               解禁
approval restricted          管理员审批
approval open                开放审批
```

手工信任一个群不会把 `local-tui` 设成超管，需要在此显式设置真实 Open ID。转移后原超管成为普通成员；目标若已被拉黑，需先解禁。TUI 不调用全量群成员 API，不会宣称手输 ID 已被飞书验证为真实群成员。

运行服务持有群权限写入锁时，外部 TUI 的群权限页只读，群聊开关也不能从外部 TUI 修改；可以使用运行中的群命令，或停止服务后再在本机管理。异常退出可能留下 `group-access.writer.lock`，先确认锁中 PID 对应进程已退出，再清理该锁文件，不能在服务运行时直接删除锁。

权限文件位于 `~/.chat-codex/state/bridge/group-access.json`（可随配置改变）。schema 1 首次写入前备份到 `group-access.json.v1.bak`，再写 schema 2。旧预留角色不会获得权限。状态文件损坏、策略未知或 scope 冲突时群权限暂停，其他渠道仍可继续工作；停止服务后恢复备份或修复原文件。回退旧程序时先恢复对应版本备份，不让旧程序继续改 schema 2。

## 真实租户验收清单

本轮没有使用真实机器人凭证、发送真实群消息或发布服务。部署后的管理员可按此表验证，并把时间、机器人账号、群 ID、结果和必要的脱敏日志补入测试报告：

- 两个群分别配对，超管、两个管理员和普通成员使用不同真实账号；检查权限与黑名单不会串群，也不影响私聊。
- 文本、图片、文件分别测试：关闭开关、无 @、仅 @所有人、明确 @机器人。
- 名称同名和更名后权限不变；真实 @成员 的管理命令指向正确 Open ID。
- 管理员审批、文件发送、普通成员黑名单成功；越权目标被拒；确认码超时、换人确认和角色中途变化被拒。
- 两条并发审批按编号处理；两人同时处理同一条只能成功一次；撤权后批准和文件发送被阻止。
- 文件上传、reply 失败回退 create、平台资源权限不足、WebSocket 断线重连与服务重启均记录真实结果。
