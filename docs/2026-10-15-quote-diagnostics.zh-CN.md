# 引用消息诊断与日志展示

日期：2026-10-15。状态：本轮引用日志和回执关联已完成本地实现与自动化验收。

## 问题与结论

现有微信引用会传给 Codex，但终端入站 transcript 只展示本次输入，没有展示被引用的消息 ID、正文来源或恢复结果。缓存查询仅返回记录或 `undefined`，无法区分未命中、未启用和读取失败。统一占位文字“未缓存或已过期”可能被模型解释为已经确认过期，实际上没有这项证据。

引用 ID 只能定位消息，不能凭空恢复正文。升级前没有记录的消息、其他账号／会话的消息、已清理的记录都可能未命中；不会跨账号查找，也不根据未命中推断过期。

诊断字段与 `quotedMessage` 分开，日志不额外复制引用正文、局部选中内容、原始微信数据或凭据。正常对话 transcript 仍按既有方式显示本次消息正文。新增信息用于本机排查，不向微信增加提示消息或发送次数。

缓存未命中统一报告“未记录或已清理，无法确认过期”；缓存禁用、未配置目录、数据库不可用和缺少引用 ID 分别说明。局部引用无法还原时区分缺少正文和选择校验失败，保留原有全文回退行为；附件是否可用单独说明。

## 展示及定位方式

以下为模拟数据的显示示例，普通 Console 与 TUI 使用同一份格式化逻辑：

```text
收到 微信 <= user
  消息 ID: 18446744073709551614
  引用消息 ID: 18446744073709551615
  引用正文: 本地缓存未命中（未记录或已清理，无法确认过期）
  局部引用: 原文不可用，无法还原选中片段
  解释这个
```

收到的消息都显示本条 ID；有引用时再显示引用 ID 和状态。发送成功后的正文、进度、旁白、审批和媒体 transcript 接收真实回执：有 `serverMessageId` 时显示服务端 ID，并在不同于客户端 ID 时同时显示客户端 ID；只有普通 `messageId` 时标注“发送消息 ID”，不冒充服务端 ID。未投递的本地进度和发送失败不会产生成功回执。

后续引用的 ID 可以与先前的入站 ID／服务端发送 ID 对照。媒体带说明时，微信 adapter 分开发送说明和附件，当前 transcript 显示 adapter 返回的最后一条（附件）回执，不能据此声称完整记录了中间每一条发送记录。

诊断元数据放在当前正文之前，Console 的正文截断不影响它；ID 控制字符转义、异常超长 ID 限制到 256 字符，正常 20 位 uint64 ID 完整保留。终端原有最近 300 条日志保留规则不变，没有新增持久日志文件，升级前没记录的 ID 也不会回填。

## 实现位置与边界

- 通用协议：`ChannelMessage.quoteDiagnostics` 只包含状态枚举；`quotedMessage` 继续保留 ID、全文及可验证的选中片段，用于 Codex 输入。诊断字段不进入模型的引用上下文。
- 微信缓存：`lookup()` 区分 `hit/miss/disabled/unavailable`，旧 `find()` 保留兼容。缺少缓存目录和引用 ID 由 adapter 区分。
- 展示：`src/logging/message-context.ts` 统一生成中文诊断，Console／TUI 共同使用；`BridgeDelivery` 只传递已有回执，不增加发送请求。
- 真实微信手机端仍未联调；本次没有读取真实用户的历史日志、登录态或发送测试消息。所引述的那次失败尚不能定位为具体缓存原因，需新日志证据。
- 2026-10-15 后续已随 Codex／微信协议适配提交并推送到 `origin/main`，检查点 `2aa8101`。重新构建并重启使用这份源码的服务后才会看到新日志，当前运行的进程没有被改动。

## 引用输入策略与飞书现状补充

2026-10-15 后续讨论：普通引用优先保持原意，让 Codex 知道用户引用了什么。本轮保留当前“本次输入 + 被引用消息正文 + 可验证的选中片段”形式，不追加自动摘要、裁剪或去重策略。引用专用输入预算此前仅是针对极长正文的建议，并未实现，也不作为本轮新增必做项；不能据此宣称任意长度引用都不会增加上下文占用。

微信原文由中间件从入站附带内容或按消息 ID 查询本地缓存取得，然后由 `textWithQuotedMessage()` 附加到普通 Codex 输入。只处理被引用的消息，不因引用额外重载整段会话历史。

本批日志工作完成时的飞书现状：出站 `FeishuAdapter.sendFeishuMessage()` 已优先调用 `im.message.reply` 回复来源消息，失败后退回普通发送；当时入站仍未按 `parent_id` 读取父消息正文。用户随后确认补齐此项；现在私聊与群聊已通过权限后的引用恢复 hook 读取直接父消息，接入现有 `quotedMessage`，并追加本地恢复状态日志。实现、使用方式和 655 项全量测试见[飞书入站回复原文适配](2026-10-15-feishu-reply-context-adaptation.zh-CN.md)。

## 日志后续整理方向

本轮先补齐引用这一条链路。整个日志面板可以继续按“收到消息 → 引用恢复 → Codex 执行／提问 → 渠道投递”组织事件，以消息 ID、session ID、turn ID 关联；默认显示中文结果和可采取的动作，技术字段放在明细。全局日志分组、筛选、持久文件及发送重试时间线单独实施，不能把日志展示改进当成长文本或微信限流修复。

本机日志不会补回已经缺失的历史记录，真实手机引用仍需单独验证。
