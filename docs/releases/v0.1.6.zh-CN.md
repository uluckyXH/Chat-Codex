Chat-Codex v0.1.6 主要聚焦 Codex CLI 0.162.1 协议适配、微信 2.4.10 收发与引用兼容、飞书群聊开放及权限管理，并修复旁白碎片化、审批和连接恢复等问题。

## 安装 / 升级

npm `0.1.6` 由维护者单独发布；请在 npm 版本发布后执行：

```bash
npm install -g chat-codex@0.1.6
chat-codex --version
chat-codex
```

升级前停止旧进程，升级后重新启动。运行需要 Node.js 22+；微信持久引用缓存建议使用 Node.js 22.13+ 或更新版本，不支持内置 SQLite 时会降级为普通收发。

飞书群聊默认仍关闭，需要在 TUI 渠道详情或已配对私聊中通过 `/group on` 显式开启。首次使用和角色权限见[飞书群聊使用说明](https://github.com/uluckyXH/Chat-Codex/blob/v0.1.6/docs/feishu-group-chat-guide.zh-CN.md)。群权限数据首次写入新版格式前会保留 `.v1.bak` 备份；回退旧程序时需恢复对应旧版备份。

## 新增项

- 【新增】对齐 Codex CLI 0.162.1 app-server 协议，区分过程旁白、阶段答案、最终答案和异步问题，阶段结果可在任务执行中送达。
- 【新增】支持 Codex 非阻塞用户提问，任务可以继续运行；按提示中的独立题目编号选择选项或补充自定义回答，避免旧问题回复误匹配新任务。
- 【新增】适配向已运行终端输入内容的 `writeStdin` 审批，清楚展示待输入内容，微信和飞书可处理；飞书私聊提供对应的允许／取消卡片。
- 【新增】正式开放飞书群聊接收入口，提供超管、管理员、黑名单、审批策略和本机权限管理界面；群消息仍需配对、成员登记并明确 @Bot。
- 【新增】飞书群聊支持带编号的多人审批、共享附件，以及按原始发起人权限校验的文件发送；管理变更使用限时确认码。
- 【新增】微信对齐 `@tencent-weixin/openclaw-weixin` 2.4.10 消息协议，支持大整数消息 ID、服务端发送回执、完整引用和局部引用。
- 【新增】微信引用增加按账号／渠道／会话隔离的持久缓存和媒体副本，重启后可恢复仍在有效期内的引用内容。
- 【新增】飞书私聊和已启用的群聊支持恢复直接被回复消息的文本、Markdown 和可访问附件，交给 Codex 作为引用上下文。

## 优化项

- 【优化】用户输入支持多题依次回答、选项补充和自定义内容；命令及问题答案与历史引用分开处理，不因回复题目而重新加载整段上下文。
- 【优化】恢复会话时区分用户请求的设置和 Codex 实际生效的模型、协作模式与权限；未知审批范围不自动扩大授权。
- 【优化】会话历史使用有界分页，处理重复游标、历史回退和失效结果，避免旧内容覆盖新状态。
- 【优化】Goal 同步用户操作来源和状态变化；任务完成、失败、中断与上游重试分别显示。
- 【优化】`/debug` 补充握手版本和协议适配信息，工作目录、权限与连接异常提供更明确的诊断。
- 【优化】日志增加本条／引用消息 ID、缓存命中与缺失原因、局部引用恢复结果及发送回执，便于区分本地观察与实际送达。
- 【优化】旁白在每条消息生成完成后整体记录和投递，无需等待整个任务结束；brief 合并完整消息并保留中间正文。
- 【优化】增加独立安装包验证命令 `npm run test:package`，检查完整模块清单、打包内容、依赖树和安装后的 CLI／核心模块。

## 修复项

- 【修复】修复 Codex 旁白被标点、换行和长度规则拆成大量碎片日志及渠道消息的问题。
- 【修复】修复旁白完成正文被跳过、相同文本被误去重、合并时丢失中间正文，以及只有旁白时兜底仅剩最后片段的问题。
- 【修复】修复定时发送与任务结束之间可能重复补发旁白的问题，前台和后台统一按消息投递回执判断。
- 【修复】修复 app-server JSON 传输异常的恢复和诊断，避免连接错误被当作正常输出；修正 exec 失败／取消状态。
- 【修复】修复 Windows 下本机 `codex` 可用但中间件报 `spawn codex ENOENT` 的可执行文件解析问题。
- 【修复】修复飞书审批字段和卡片展示、审批生命周期及发送重试问题；补齐 MP4 视频发送兼容。
- 【修复】修复微信已登录账号仍使用默认服务地址的问题，收发及相关请求使用账号保存的地址。
- 【修复】将随包依赖 axios 升至 1.20.0、qs 升至 6.16.1，并同步飞书 SDK 打包元数据，处理发布审计发现的已知问题。

本版通过构建、721 项自动化回归及 8 组独立安装包验证，生产依赖审计为 0 项漏洞；详细结果见[发布测试报告](https://github.com/uluckyXH/Chat-Codex/blob/main/reports/tests/2026-10-16-release-0.1.6.md)。真实微信／飞书送达和 Windows 实机仍需单独验收。通用长文本分段／转文件及微信限流恢复不在本版范围；微信继续保留 silent／brief 策略。
