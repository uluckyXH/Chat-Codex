## 已实现与对应证据

本轮新增 **33 项专项测试**，另更新旧群聊测试，使其验证“显式启用后可用”，保留“默认关闭”的检查。

| 设计项 | 实现与验证 |
| --- | --- |
| 明确的渠道策略 | `ChannelAdapter.groupPolicy` 显式接入；Bridge 读取注册适配器策略。非飞书前缀的 fake adapter 可测试群权限；没有接入策略的其他群渠道仍保留原有行为 |
| 接入检查顺序 | 开关与 @bot 在 adapter 入口检查；黑名单先于 help/name/pair、状态更新和附件下载；配对和手工名称登记后才允许任务 |
| 管理员权限 | 超管任免管理员；管理员可以审批、发文件、管理普通成员；不能操作自己、同级、超管或扩大审批策略 |
| 黑名单层级 | 保存操作者和当时角色；普通管理员不能解除超管、本机或历史来源不明的封禁；撤职与封禁一次提交；解禁不恢复管理员 |
| 超管恢复 | 手工信任不产生 `local-tui` 超管；本机可设置、转移、清空；缺失有效超管时暂停审批、文件及聊天管理；重复初始化不抢回旧超管 |
| 群命令与确认 | 完整目标 Open ID 或真实 mention 元数据；不使用名称授权；确认绑定 actor、route、target、revision，60 秒过期；命令在异步忙碌检查之后再次核权 |
| 审批编号 | 群内随机运行期编号；OK/NO 和兼容别名保留编号；多个 pending 无编号拒绝，跨群和旧实例编号拒绝；群内禁止会话范围批准 |
| 审批并发与失败 | 同步获得 resolving 后只回写一次；保存真实处理人和处理时间。明确未发送可恢复 pending，结果不确定则 uncertain，后续协议通知可收敛，不能盲目重试 |
| 附件与队列 | 群共享上限 5 个、TTL 10 分钟沿用已有行为；保存 sender、名称快照、message、收到时间、序号。下载、入池、消费、队列和混合 steer 批次按当前权限复查 |
| 文件输出 | `/sendfile` 普通成员不入队；排队和最终输出使用原始发起人。上传后与 reply/create 前再检查权限；撤职、封禁或服务停止后停止后续文件发送。文件审计包含消息 ID、session 和授权版本 |
| schema 与写盘 | group-access 独立 schema 2；首次写前 `.v1.bak`，文件权限 0600；旧预留角色不激活。坏 JSON、空文件、未知 schema/策略或 scope 冲突均拒绝新授权，不阻止其他渠道状态操作 |
| 故障一致性 | 角色修改先写盘再更新内存；写盘失败测试验证原角色与重启后的状态不变。审计上限 500 条，既有文件发送成功不会因后续审计失败被错误报告为发送失败 |
| TUI | 恢复渠道开关确认；群详情入口支持超管修复、角色、黑名单、策略、成员和最近审计。确认取消不写入；旧 revision 被拒绝；运行实例持有写入锁时外部管理只读 |

## 运行与恢复说明

- 在更新代码后构建并重启；TUI 渠道详情开启群接收，或在已配对私聊 `/group on`。
- 运行时群权限状态只有一个写入者。外部 TUI 修改需先停止服务；运行内群命令使用同一个权限服务。写入锁为 `group-access.writer.lock`。
- 正常停止会释放锁。异常退出留下的锁不自动抢占；确认锁中 PID 对应进程已退出后再清理，步骤已写进使用说明。
- 旧数据迁移只写群权限文件，不修改其他渠道的信任、绑定、登录态或策略。回退旧程序前恢复 `.v1.bak`。
- 权限变更不会撤回已经进入 Codex 上下文的文字或已交付远端的动作；只阻止尚未获得执行许可的后续受限动作。
