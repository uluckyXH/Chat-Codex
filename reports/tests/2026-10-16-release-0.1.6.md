## 按用户补充要求优化验证

- 相关提交改为点击可直达 GitHub 的链接，12 个短号均经本地 Git 校验并在 URL 中固定为完整 commit SHA。
- 新增 `npm run test:package`：执行真实 prepack，核对包清单、源码对应的全部运行模块、敏感文件排除和 SHA-512；在隔离 prefix 中安装同一个 tarball，检查依赖树、CLI 版本／帮助／可执行入口、飞书 SDK、实际依赖版本及 10 个核心模块。`--keep` 保留经过验证的 tarball 供实际发布，否则成功后清理。
- 审计发现根包的随包标记会使普通 install／audit fix 跳过旧依赖。临时移除本地 bundleDependencies 后定向更新 axios／qs，再恢复原配置并同步 shrinkwrap；最终仍随包提供飞书 SDK。仅三个传递依赖版本变化，不升级飞书 SDK 主包。
- prepack 不再写死旧 axios 版本范围，而是读取本项目 overrides，避免打包元数据与实际安全版本再次偏离。

## 用户手动发布 npm

在项目目录拉取此次发布代码，然后登录并发布：

```bash
git pull --ff-only
npm ci
npm login --registry=https://registry.npmjs.org
npm publish --registry=https://registry.npmjs.org --access public --tag latest
npm view chat-codex version --registry=https://registry.npmjs.org
```

项目目录下的 `npm publish` 自动执行 `prepublishOnly` 全量测试和 `prepack` 构建／SDK 元数据同步。若 npm 提示浏览器登录或二次验证，由账号持有人按提示完成。最后的版本查询应返回 `0.1.6`。用户也可发布上面那份已经过安装验证的 tarball；直接发布 tarball 不再次执行项目的发布前测试钩子。
